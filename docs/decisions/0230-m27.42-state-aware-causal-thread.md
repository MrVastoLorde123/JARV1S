# M27.42 — State-Aware Causal Thread

## Decision

The cross-instrument operation thread now expresses runtime state at each instrument node instead of only showing operator location.

## Node semantics

- CHAT / INTENT becomes active during live intake and attention-aware when the user is required.
- CONTROL / ACTION becomes waiting when execution is held and blocked when resource pressure prevents safe progression.
- MIND / CONTEXT remains active while reasoning, learning, or related runtime activity is present and waiting when the operation is carrying context without execution progress.
- CAPABILITIES / ABILITY becomes blocked when no healthy model lane exists and waiting when pressure defers invocation.

## Causal explanation

The active node exposes the reason for its state. The thread therefore answers three questions directly: where the operation is, what state it is in, and why that state exists.

## Boundaries

This remains a presentation layer over `JarvisSnapshot`. It does not create execution authority, infer permission, mutate backend state, or expose private model reasoning.

## Principle

**The thread should show where the operation can move, where it cannot move, and why.**
