# M51.1 — Confirmation Boundary Decision

M51 introduces explicit confirmation as a distinct boundary after scheduling/notification proposals.

A confirmation response records what the user explicitly confirmed or declined. It does not transform that response into authorization. This preserves the separation:

`proposal → confirmation → authorization → execution`

The confirmation contract is lineage-bound to the exact M50 proposal set and proposal identity, preserves unresolved uncertainty, and exposes explicit non-authority/non-execution state.
