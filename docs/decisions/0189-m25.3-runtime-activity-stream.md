# Decision 189 — M25.3 Runtime Event / Activity Stream Boundary

## Status
IMPLEMENTED / VERIFIED LOCALLY

## Purpose
M25.3 gives JARVIS a coherent observational stream before a visual interface exists.

The runtime activity stream records immutable observations of interface/runtime transitions. It exposes what happened, its logical position in the stream, who/session context it belongs to, which operation was involved, and whether the request was accepted, rejected, or failed. It does not redefine the semantics of M24 or grant execution, authority, persistence, truth, or certainty powers.

## Scope

```text
InterfaceRequest
      ↓
SelfImprovementInterfaceBackend
      ↓
SelfImprovementOrchestration
      ↓
ObservableInterfaceOrchestration  ← M25.3 observer seam
      ↓
RuntimeActivityRecorder
      ↓
RuntimeActivityStream
      ↓
Future GUI / CLI / API / Voice
```

## Boundary rules

- `RuntimeActivityEvent` is an immutable observation artifact.
- Event identity, sequence, session identity, actor identity, request identity, operation, kind, status, stage, summary, and metadata are explicit.
- Event metadata is recursively frozen.
- Stream order is explicit and contiguous; gaps are rejected.
- Stream snapshots and incremental reads are immutable tuples.
- The stream is in-memory observational state only; it is not durable persistence.
- The recorder does not copy or reconstruct M24 artifacts into events; it records bounded metadata about the transition.
- Accepted responses map to `RESPONSE_EMITTED`.
- Rejected responses map to `REQUEST_REJECTED`.
- Failed responses map to `REQUEST_FAILED`.
- Unexpected orchestration exceptions are observed as failed activity and then re-raised; the observer must not hide runtime failures.
- Request/response identity mismatches are rejected.

## Explicit non-powers

```text
Activity Stream ≠ Authority
Activity Stream ≠ Executor
Activity Stream ≠ Persistence
Activity Stream ≠ AI Provider
Activity Stream ≠ Truth Source
Activity Stream ≠ Decision Engine
```

The activity stream exists so downstream interfaces can explain and visualize runtime behavior without becoming responsible for that behavior.

## Design consequence

M25 now has a machine-readable activity surface beneath the eventual visual interface. The future UI can consume immutable observations rather than reaching into core objects or inventing its own lifecycle semantics.
