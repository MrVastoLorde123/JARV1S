# Decision 0202 — M27.10 Interface Solidification

**Status:** IMPLEMENTED ON feature/m27.10-interface-solidification / AWAITING LOCAL BUILD VERIFICATION

M27.10 hardens the V2 interface direction before backend integration. The interface is treated as a set of distinct operating surfaces rather than a generic dashboard.

## Surface model

- **HOME** — orientation and awareness: what matters now, attention, recent intelligence, active work, system fabric, device and model state.
- **CHAT** — interaction container with specialized sub-surfaces: Conversation, Workspace, Research and Planning.
- **WORK** — the project-control surface. Work objects expose state, progress, workspace, plans, feedback and a user-facing pause/resume control.
- **MIND** — standalone core environment for JARVIS's internal world. It is explorer-first and provides dedicated Explorer, Graph and Thinking views.
- **CAPABILITIES** — capability fabric: models, plugins, integrations, workers, skills, devices and automations as things JARVIS can use and explain.
- **SELF** — self-observation: runtime pressure, resource policy, model coordination and internal activity.

## MIND direction

MIND is deliberately not folded into HOME. Its long-term shape is an application-explorer-like cognitive environment in which domains, records, provenance, relationships, context and thought can be inspected and navigated. Relationship graphs are a first-class part of this environment.

The current UI is a structural prototype of that direction; it does not claim that the displayed domains are already backed by real cognitive state.

## Invariants

- UI surfaces represent JARVIS capabilities and state; they do not become execution authority.
- HOME remains distinct from MIND and must not absorb MIND's internal complexity.
- WORK pause/resume is a user-facing control concept only until routed through backend authority boundaries.
- Research material remains evidence/context; thinking is explicitly separate from collection.
- Planning remains proposal-oriented until backend confirmation, policy, authorization and execution boundaries accept it.
- Workspace roots are explicit and literal; selecting a directory does not grant arbitrary authorization.
- The gateway remains replaceable between renderer and JARVIS Core.
