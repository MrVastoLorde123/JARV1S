# M28.11 — Agent Runtime Composition Over Existing Workforce

## Decision
The world-facing `AgentEntity` is a projection of JARVIS's existing workforce and execution system. It is not a replacement workforce implementation.

## Composition
- `WorkerDefinition` remains the reusable worker/archetype contract.
- `WorkerAssignment` remains the bounded delegated-work contract.
- `WorkerRegistry` remains authoritative for worker/assignment compatibility.
- `BoundedWorkerRuntime` remains the execution path and continues through M7/M8 authority and execution boundaries.
- `WorkerReport` remains the worker result/evidence boundary.
- `AgentEntity` is the runtime world identity of one concrete worker instance.
- `AgentRuntime` composes the existing worker contracts into an observable lifecycle without creating authority, permissions, provider handles, or credentials.

## World-facing additions
The composition layer exposes:
- `AgentRoute` — current and future landscape movement for one agent instance.
- `WorkLineage` — user request through plan, assignment, agent, execution, evidence, and handoff identities.
- `EvidenceReference` / `EvidenceBundle` — provenance-bearing source references produced by work.
- `AgentHandoff` — explicit result transfer back into JARVIS, including evidence linkage and acceptance state.

These objects are observational/provenance structures. They do not authorize execution, prove truth, grant capability, or decide acceptance authority.

## Lifecycle
A real agent may now be represented as:

`ASSIGNED → TRAVELLING → EXECUTING → RETURNING → HANDOFF → RETIRED`

The UI must derive visible movement and presence from these backend entities rather than inventing worker behavior.

## Example
For research work JARVIS may validate a `researcher` worker assignment, instantiate `Researcher-07`, route it from `AGENTS` to `MODELS`, execute through existing workforce/execution boundaries, attach evidence, return the instance, hand off the report, and retire the agent.

## Boundary
Simple work does not require an agent. JARVIS may keep a task native to itself when delegation provides no benefit.
