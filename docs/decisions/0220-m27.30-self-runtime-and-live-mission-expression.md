# M27.30 — SELF runtime and live mission expression

## Decision

The desktop interface should express meaningful JARVIS runtime state through the environment itself, while keeping presentation subordinate to authoritative backend state.

This milestone establishes three UI contracts:

1. **Live Missions is persistent connective tissue.** The footer is mounted from the Mission Spine and reads the same selected project and derived mission state used by HOME and CONTROL.
2. **SELF is a runtime environment, not a resource dashboard.** Resource telemetry, model fleet state, current operation and structured observations are presented as coordinated lanes using the existing `JarvisSnapshot` contract.
3. **System state can shape the whole environment.** Connectivity, pressure, attention and operating mode are exposed through document-level state attributes so future surfaces can react consistently without duplicating state logic.

## Constraints

- No invented model cognition or private chain-of-thought is rendered.
- No new authority is introduced in the UI.
- Existing `App.tsx` remains the host shell; additive portals/controllers are preferred over rewriting the monolith.
- Local LLMs remain interchangeable engines beneath JARVIS orchestration rather than becoming the identity of JARVIS.

## Result

The interface now has a foundation for the intended direction: actual orchestration can become visible through shared mission state, model assignment, resource policy, structured observations and global environmental expression as the backend becomes more capable.
