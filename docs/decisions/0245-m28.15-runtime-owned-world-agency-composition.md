# M28.15 — Runtime-Owned World Agency Composition

## Decision

Attach the M28 world model to the canonical `JARVISRuntime` through the existing M9.5 delegation and M9.2 bounded worker execution path.

`AgentWorldRuntime` owns the runtime's current concrete `AgentEntity` projections and retained `WorkerAssignment` identities while work is active or being completed. It is runtime state, not a second persistence database or source of execution authority.

## Canonical flow

`JARVISRuntime → M9.5 DelegationCoordinator → WorkerAssignment → M9.2 BoundedWorkerRuntime → AgentWorldRuntime → AgentEntity lifecycle → WorldObservationProjector → WorldObservation → M28.14 HTTP transport`

## Composition rules

- `DelegationCoordinator` remains responsible for validating and deterministically ordering delegated assignments.
- `WorkerRegistry` remains the authoritative compatibility boundary for worker definitions and assignments.
- `BoundedWorkerRuntime` remains the only worker execution path and continues to consume already-authorized M7 preparations through M8.
- `AgentRuntime` remains the world identity/lifecycle composition layer.
- `AgentWorldRuntime` retains the concrete runtime entities and their exact assignment objects so an observed agent can always be traced back to the real delegated work.
- `WorldObservationProjector` remains read-only and derives the coherent frontend observation from those runtime entities.
- `JARVISRuntime` is the application-facing composition root and exposes explicit world delegation, instantiation, execution, and observation seams.
- The HTTP transport reads `JARVISRuntime.observe_world()`; it does not create or own world state.

## Why this is not a WorldStateStore

The retained mapping exists inside the runtime that owns the work lifecycle. It is not a parallel persistence layer, cache pretending to be authoritative, or UI-specific database. It disappears with the runtime unless an existing JARVIS persistence boundary later gives these entities durable semantics.

## Lifecycle

A delegated world worker begins as `ASSIGNED`, becomes `EXECUTING` immediately before the real M9.2 worker run, then moves through `RETURNING` and `HANDOFF`. Successful completed work is retired after handoff. Partial or blocked work remains represented through its non-retired lifecycle state until a later runtime decision changes it.

## Authority boundaries

M28 remains observational. Agent existence in the world is backed by an actual M9 assignment; world observation does not grant authority, permissions, credentials, execution rights, or truth.

## Consequence

The browser can now be connected to a real runtime-owned world projection without introducing a fabricated state store. The next integration step is wiring the application process to construct one configured `AgentWorldRuntime`, pass it into `JARVISRuntime`, and start `serve_world_observation(runtime.observe_world)`. That is host/process integration, not another architectural layer.
