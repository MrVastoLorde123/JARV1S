# M27.38 — State-Driven Spatial Hierarchy

## Decision

Instrument layout is now treated as a runtime communication policy, not a fixed page composition.

The same backend state may change where information is placed inside CHAT, CONTROL, MIND and CAPABILITIES.

## Spatial rules

- Stable state keeps orientation first and secondary action detail low in the hierarchy.
- Attention moves the state and response path forward so the operator sees what requires them before routine context.
- Model gaps move recovery/inspection beside the state rather than leaving the operator to search for the cause.
- High resource pressure places guard state beside the primary action surface.
- Waiting states move the next transition ahead of secondary metrics because the machine is holding rather than acting.
- Context-rich MIND state gives internal context more spatial weight instead of merely adding more text.

## Boundaries

Spatial hierarchy is derived from `JarvisSnapshot` state and remains presentation-only. It does not create authority, infer permission, expose private reasoning, or change backend execution semantics.

## Principle

**Urgency changes position. Causality changes adjacency. Stability changes quietness.**
