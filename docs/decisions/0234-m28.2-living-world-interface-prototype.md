# M28.2 — Living World Interface Prototype

## Decision

Prototype JARVIS as a shared world rather than a collection of application pages.

The active UI is a single spatial environment containing the current JARVIS core, missions, context, runtime, model/ability nodes, attention, and direct input. Interaction changes focus and emphasis inside the same world instead of navigating between conventional screens.

## Principles

- The environment is the interface; pages are not the primary mental model.
- Backend state drives environmental state: activity, waiting, pressure, attention, and offline conditions change visual weight and behavior.
- Missions, context, runtime, and ability are objects/perspectives in one shared space rather than separate destinations.
- Focus is a camera/attention change, not a route change.
- Detail surfaces are transient inspection layers and must not become permanent dashboard chrome.
- Direct input belongs to the world itself.
- Existing gateway contracts remain the authority boundary; the prototype introduces no new backend authority.
- Visual ambition is constrained by comprehension: the world should feel alive without becoming a game or decorative visualization.

## Why this exists

The previous M28 prototype successfully produced a clean operating-system skin but still inherited the assumptions of an application: lenses, rails, inspectors, and destination-oriented surfaces.

M28.2 intentionally tests the stronger idea: JARVIS is a persistent environment the user enters, observes, and influences. The interface should express changing backend state spatially and continuously rather than requiring the user to open a page to discover it.

## Non-goals

- No attempt to make the UI a 3D game.
- No new backend state machine.
- No replacement of deterministic authority with visual state.
- No permanent information-dense dashboard.
