# M27.36 — State-Derived Instrument Affordances

## Decision

Operational instrument surfaces must derive their primary next-step affordance from live JARVIS runtime state.

## Rule

The same runtime signal may produce different next moves in different instruments:

- CHAT routes attention, model gaps, or held work toward the instrument that can resolve the condition.
- CONTROL keeps attention, model gaps, and waiting work visible as guarded transitions rather than pretending action is available.
- MIND routes dense context toward orchestration and sparse context toward relevant work tracing.
- CAPABILITIES routes model gaps and high resource pressure toward runtime inspection before invocation.

## Boundary

These affordances are navigation/inspection actions only. They do not grant authority, authorize execution, or create new backend state. Existing backend-owned authority and execution paths remain canonical.

## Outcome

State now changes both the appearance and the recommended next move of each instrument, strengthening the visual operating language without turning the UI into an authority layer.
