# M27.37 — State-Driven Content Density

## Decision

Instrument surfaces must adapt information density from live runtime state, not merely recolor a static layout.

The interface uses four density postures:

- **COMPACT** — stable/quiet state; secondary detail recedes so the instrument stays readable.
- **FOCUSED** — active, waiting, or elevated-risk state; the information needed for the next transition becomes prominent.
- **EXPANDED** — attention, model gaps, or rich context require additional operational explanation.
- **DEFERRED** — pressure can suppress secondary detail without hiding the fact that it exists.

Density is derived separately for CHAT, CONTROL, MIND, and CAPABILITIES because the same machine state has different meanings in each instrument.

## Boundary

Content density is presentation policy only. It does not grant authority, execute actions, alter backend state, or expose private model chain-of-thought.

## Principle

**The machine should reveal more information when the operator needs more information, and become quieter when the state is stable.**
