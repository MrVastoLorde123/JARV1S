# M37.1 — Execution Outcome / Verification Boundary

## Decision
Separate observed execution outcome from independent verification.

M36 proves that an already-authorized M7.10 preparation can pass through the existing M8.5 controlled agency runtime. Its result is an observation of what happened during the execution attempt, not proof that the intended external state was achieved.

M37 introduces bounded immutable outcome classification plus an explicit verification-input contract. An external verifier remains responsible for returning a verification decision and evidence identity.

## Boundary
- outcome classification consumes M36 agency results
- outcome classification never grants authority
- outcome classification never performs execution
- `VerificationInput` contains bounded facts for a verifier
- `VerificationDecision.VERIFIED` requires an evidence identity
- this milestone does not manufacture verification evidence
- existing verification authorities remain authoritative

## Rationale
Keeping execution observation and verification separate preserves the existing chain:

`authorization -> execution -> observation -> independent verification -> evidence`

A successful execution adapter result can therefore be surfaced as `SUCCEEDED` without implying that the intended world state has independently been verified.
