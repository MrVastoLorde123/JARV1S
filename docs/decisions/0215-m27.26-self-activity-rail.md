# M27.26 — SELF Activity Rail

## Decision
SELF internal activity should be spatially dense rather than a default vertical feed. The purpose of SELF is runtime observability: the user should be able to scan what JARVIS is doing across several internal activity dimensions without consuming the entire viewport with stacked cards.

## Layout behavior
The SELF activity region is presented as a responsive horizontal activity rail on desktop:

- activity cards share one row when space permits
- each card remains independently readable and bounded
- the rail may wrap to a second row at intermediate widths
- mobile returns to a vertical sequence for usability

The existing semantic `self-card` objects remain unchanged. This is a presentation-only transformation.

## Spatial model
The rail prioritizes scanability:

1. current/high-value self activity
2. delegation or model coordination activity
3. resource-guard/runtime activity
4. recent supporting activity

A horizontal rail communicates that these are concurrent observations of one internal system, not a chronological chat transcript.

## Boundary
No new authority, execution behavior, hidden reasoning, or canonical state is introduced. SELF only renders existing presentation-safe self-activity state.
