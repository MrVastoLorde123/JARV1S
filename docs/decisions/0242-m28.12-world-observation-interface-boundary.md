# M28.12 — World Observation Interface Boundary

## Decision
The frontend must consume a coherent world observation derived from backend state. It must not independently infer agent relationships by combining worker, project, model, research, and activity fragments.

## Backend boundary
`WorldObservationProjector` composes:
- `AgentEntity`
- `AgentRoute`
- `WorkLineage`
- `EvidenceBundle`
- `AgentHandoff`

into read-only `WorldObservation` data.

## Frontend meaning
The UI may render:
- where active agents are;
- where they are travelling;
- what assignment they belong to;
- what model/capabilities they use;
- what evidence they produced;
- where their work came from;
- what they handed back;
- whether they are still active or have retired.

The UI must not fabricate these states locally once the live backend boundary is connected.

## Transport boundary
The current repository does not expose an identified HTTP/WebSocket transport for the Vite UI. M28.12 therefore stops at a transport-neutral backend observation contract rather than introducing a second runtime server, duplicate state store, or fake live API.

A future transport adapter must expose `WorldObservation` as serialized read-only data and route commands back through existing JARVIS authority/command boundaries. It must not give the UI direct access to worker execution, capabilities, credentials, or authorization controls.

## Principle
The world is an observer of JARVIS. JARVIS does not become subordinate to the world renderer.
