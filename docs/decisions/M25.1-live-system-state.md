# M25.1 — Live System State

## Decision
M25 formalizes the existing runtime-backed cockpit feed as a typed live system-state contract. The UI continues to consume runtime-owned endpoints; M25 does not create a second state store or authority path.

## Contract
- `/api/control-plane`, `/api/world/observation`, and `/api/capabilities` remain the runtime observation surfaces.
- Runtime payloads are normalized into a typed `LiveSystemState` model.
- Observation freshness is explicit; missing timestamps are not treated as fresh.
- Runtime availability, degradation, and authority remain separate concepts.
- The live-state model is read-only and contains no execution capability.
- Invalid progress, state, cursor, and optional string values are normalized to safe representations.

## Acceptance
`verify_m25_live_system_state.py` verifies the existing polling surface and the M25 state model. The UI production build compiles the new TypeScript contract, while the established core regression remains the regression gate.
