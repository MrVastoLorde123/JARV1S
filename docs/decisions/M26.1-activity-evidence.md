# M26.1 — Activity & Evidence

## Decision
M26 formalizes the cockpit's existing runtime activity stream and verification evidence projection as a typed, observation-only contract. Activity describes what the runtime reports; evidence describes bounded proof references already produced by runtime verification.

## Contract
- Runtime activity remains sourced from the existing read-only control-plane projection.
- The monotonic observation cursor remains runtime-owned.
- Activity is bounded operational metadata, not private model reasoning.
- Evidence references are bounded identifiers, status, summary, time, and optional source-event linkage.
- Missing or malformed activity/evidence fields normalize to safe unknown/null values rather than becoming UI truth.
- The M26 contract contains no tool invocation or execution surface.

## Acceptance
`verify_m26_activity_evidence.py` proves the existing cockpit renders runtime activity and verification state and that the M26 contract exposes typed normalization without a direct execution path.
