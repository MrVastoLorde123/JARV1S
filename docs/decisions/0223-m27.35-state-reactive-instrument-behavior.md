# M27.35 — State-Reactive Instrument Behavior

## Decision
Operational surfaces must express runtime state differently according to their role in the machine.

CHAT reacts as an intent intake boundary: attention becomes an explicit interruption, resource pressure becomes a routing condition, waiting remains visible, and model availability can hold downstream routing without implying execution.

CONTROL reacts as an action boundary: active work, waiting transitions, resource pressure and model gaps change the execution posture while authority remains explicit.

MIND reacts as a context field: context depth changes the visual density of the field, while learning activity is surfaced as context rather than truth or authority.

CAPABILITIES reacts as an ability boundary: unavailable resources are visually diminished, model gaps can close the invocation gate, and resource pressure becomes visible at the capability boundary.

## Rule
Backend state changes → each instrument changes according to its operational meaning. Shared state must not collapse into one generic status treatment.

## Constraint
Visual state must remain derived from `JarvisSnapshot`; the interface must not invent cognition, authority, execution, or capability availability.
