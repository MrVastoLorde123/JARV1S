# M27.25 — SIGNAL Acknowledgement and Interaction

## Decision
SIGNAL must distinguish between being surfaced, being seen by the user, and being explicitly handled.

## Interaction states

- `SURFACED` — JARVIS selected the signal for presentation.
- `ACKNOWLEDGED` — the user explicitly marked the signal as seen.
- `RESOLVED` — the user explicitly marked the signal as handled.

These states are interface-session facts. They are not inferred from elapsed time, focus, hover state, or visibility alone.

## Behavior
`SEEN` changes the current signal to `ACKNOWLEDGED`. `HANDLED` changes it to `RESOLVED` and preserves the acknowledgement timestamp. A new or materially changed signal remains eligible to surface independently of an earlier interaction.

Resolved signals receive stronger temporary suppression, but resolution never mutates the canonical project, attention, execution, or learning state.

## Boundary
The interaction ledger remains presentation/session state. It does not grant authority, execute actions, dismiss canonical attention conditions, or assert that an underlying system condition is actually fixed.

The interface may record that the user said a signal was handled; only canonical runtime state can establish whether the underlying condition is actually resolved.
