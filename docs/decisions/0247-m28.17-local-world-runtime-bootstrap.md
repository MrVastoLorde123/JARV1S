# M28.17 — Local World Runtime Bootstrap

## Decision

The local launcher may construct `AgentWorldRuntime` only through a real M9/M8 composition. Until a concrete local worker definition and authorized execution adapter exist, the bootstrap uses an empty `WorkerRegistry` and an explicit unavailable M8 adapter.

`UnavailableExecutionAdapter` is a truthful integration boundary. It returns a typed execution failure rather than pretending to perform work. Because the registry starts empty, no world agent can be instantiated by default.

## Composition

```text
Local launcher
    ↓
create_local_world_runtime()
    ↓
WorkerRegistry (empty until real workers are configured)
    ↓
BoundedWorkerRuntime
    ↓
ExecutionRuntime
    ↓
UnavailableExecutionAdapter
    ↓
AgentWorldRuntime
    ↓
JARVISRuntime
    ↓
M28.16 HTTP host
```

## Boundary retained

- M9 still owns worker identity, assignment bounds, delegation, and worker execution.
- M7/M8 still own authorization and concrete execution.
- M28 only owns the runtime-facing `AgentEntity` projection and observation.
- No demo worker, automatic agent, fake task, or UI-only world state is created.

## Local activation

When `JARVIS_WORLD_HTTP=1` is enabled, the local launcher now constructs this real M28 runtime and passes it into `JARVISRuntime`. The existing M28.16 host can therefore expose a truthful world observation immediately: an empty world is represented as an empty world, not simulated activity.

## Next boundary

The next implementation is not another transport layer. It is configuration of the first legitimate M9 worker definition and the existing authorized M7/M8 execution path that can produce real agent activity.
