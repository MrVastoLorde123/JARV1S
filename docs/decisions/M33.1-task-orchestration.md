# M33.1 — Bounded Task Orchestration

## Decision
JARVIS gains an explicit orchestration contract between the immutable M32 `WorkPlan` and the existing execution/runtime boundaries.

Orchestration tracks the state of each planned step, selects the next ready step deterministically, and derives bounded work progression from observed step state.

## Invariants
- Every orchestration instance is anchored to one immutable `WorkPlan`.
- Plan order and step identity are preserved exactly.
- Dependency readiness remains delegated to M32 planning semantics.
- Only one deterministic next step is selected when a step is ready.
- Active, blocked, and failed states halt progression rather than create substitute authority.
- Completion is reached only when every planned step is complete.
- Orchestration state is immutable; updates return a new state.

## Authority Boundary
Orchestration does not authorize, invoke, execute, or verify consequential actions. `CoordinationDecision.START_STEP` identifies the next bounded work item; it is not an execution request or authorization grant.

Existing M7/M8 authorization and execution, including M8.5 controlled multi-step agency, remain authoritative for consequential execution.

## Relationship to Dynamic Agency
Work roles and agent assignments remain operational context. Orchestration does not create permanent autonomous agents, grant permissions, or turn role selection into authority.
