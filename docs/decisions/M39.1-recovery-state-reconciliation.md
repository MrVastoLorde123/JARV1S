# M39.1 — Recovery to Work State Reconciliation

## Decision

M39 introduces a deterministic reconciliation boundary between an already-derived M38 `RecoveryDecision` and the M31 operational `WorkState` substrate.

The reconciliation records the operational consequence of recovery:

- `COMPLETE` -> terminal `WorkStage.COMPLETE` / `WorkStatus.COMPLETE`
- `CONTINUE` -> active `WorkStage.PLANNING` with the bounded proposal as the next work step
- `STOP_BLOCKED` -> blocked work state with an explicit recovery blocker
- `STOP_UNCERTAIN` -> blocked verification state with an explicit uncertainty blocker
- `STOP_REJECTED` -> failed terminal work state when no bounded continuation exists

## Boundaries

- M38 remains authoritative for recovery disposition.
- M31 remains authoritative for operational work state.
- M39 does not authorize, execute, verify, invoke tools, select providers, or create credentials.
- Reconciliation is a projection of an existing decision, not a new decision authority.
- Recovery, work state, execution, authorization, and evidence remain distinct identities.

## Rationale

M38 could determine whether work should complete, continue, stop blocked, stop uncertain, or stop rejected. Without a state projection, that result remained detached from the operational lifecycle. M39 closes that gap while preserving the existing authority walls.
