# M28.3 — Living World Attention Field

## Decision

The JARVIS interface experiment continues as a shared world rather than a collection of application pages. User focus changes the state of one environment instead of navigating between destination screens.

## Interaction language

- FOCUS is spatial. Selecting a mission, context, runtime, or ability changes emphasis, scale, opacity, and causal traces in the same field.
- DETAIL is transient. Inspection appears near the lower field as a contextual horizon and should recede rather than become a permanent panel hierarchy.
- SYSTEM STATE is environmental. Waiting, guarded, attention, and offline states alter the world’s activity and visual weight, not merely a status label.
- CORE remains the stable center of the environment. It is not a navigation home in the conventional sense.
- DIRECT INPUT remains embedded in the world so intent can enter without opening a separate chat destination.

## Restraint boundary

The prototype must not drift into a game HUD, decorative sci-fi command center, or conventional dashboard. Visual effects are acceptable only when they communicate state, focus, causality, or presence.

## Architectural boundary

This experiment is presentation-only. Existing `demoGateway`, contracts, and backend authority boundaries remain unchanged. The UI may reflect system state but cannot create authority from visual emphasis.

## Open questions for user validation

1. Does the shared field feel like entering JARVIS rather than opening an application?
2. Is the spatial metaphor understandable without labels explaining every object?
3. Does transient detail provide enough control without recreating panels and pages?
4. What should the user experience when JARVIS is actively thinking, working, learning, or waiting for input?
5. Which physical metaphor best represents persistent context: orbit, field, landscape, graph, or something quieter?
