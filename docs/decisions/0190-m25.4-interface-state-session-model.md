# Decision 190 — M25.4 Interface State / Session Model Boundary

## Status
IMPLEMENTED / VERIFIED LOCALLY — HARDENED FOR INTERLEAVED SESSIONS

## Purpose
M25.4 turns the M25.3 runtime activity stream into a coherent per-session interface view.

The session model is a derived projection of immutable activity events. It provides downstream interfaces with a stable summary of observed session activity without becoming a second source of truth, redefining M24 semantics, or inventing authoritative runtime state.

## Scope

```text
RuntimeActivityEvent
        ↓
InterfaceSessionStateProjector   ← M25.4
        ↓
InterfaceSessionState
        ↓
Future Interface Adapter / UX
```

## Boundary rules

- `InterfaceSessionState` is an immutable derived observation, not authoritative runtime state.
- Session identity, actor identity, event count, first/last sequence, latest event identity, latest operation, latest activity kind, latest status, latest stage, and observed active state are explicit.
- Session state is derived only from `RuntimeActivityEvent` values.
- Events from different sessions never mix into one projection.
- A session actor identity is established by its first observed event and conflicting later actor identity is rejected.
- Event sequences for a session must advance strictly by global stream position; gaps caused by other sessions are valid.
- `REQUEST_RECEIVED` derives `is_active=True`.
- `RESPONSE_EMITTED`, `REQUEST_REJECTED`, and `REQUEST_FAILED` derive `is_active=False`.
- An active flag is an observation of the latest recorded activity, not a claim about hidden runtime execution.
- Projection snapshots are immutable.
- The projector is in-memory interface state only; it is not durable persistence.
- No M24 artifact is copied into session state.
- `event_count` counts only events belonging to that session and therefore may be smaller than the global sequence span.

## Explicit non-powers

```text
Session Model ≠ Authority
Session Model ≠ Runtime Source of Truth
Session Model ≠ Executor
Session Model ≠ Persistence
Session Model ≠ M24 State Machine
Session Model ≠ AI Provider
Session Model ≠ Truth / Certainty
```

## Design consequence

M25 now has a coherent per-session view that a future interface adapter can consume without reaching into core lifecycle objects. Global runtime sequencing remains global while session projections retain only their own observed events, allowing multiple sessions to interleave safely.
