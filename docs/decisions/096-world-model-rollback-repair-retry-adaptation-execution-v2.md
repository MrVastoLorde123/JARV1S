# M23.65 — World Model Rollback Repair Retry Adaptation Execution v2

## Status
IMPLEMENTED / AWAITING LOCAL VERIFICATION

## Boundary
M23.65 is the execution boundary after M23.64. It consumes exactly one immutable READY adaptation-handoff artifact and invokes only an explicitly supplied external executor capability against that exact handoff payload.

The core execution service records an immutable execution result. It does not derive new authority, rewrite the handoff, broaden scope, schedule work, persist state, update policy, or learn from the result.

## Contract

- Consumes exactly one `EnvironmentWorldModelRollbackRepairRetryAdaptationHandoffV2` artifact.
- `READY` handoff may be executed only when its authorization remains `AUTHORIZED` and its proposal-scoped authorization matches the exact proposal fingerprint.
- `BLOCKED` handoff produces `REJECTED` execution evidence and cannot invoke an executor.
- The executor capability is supplied explicitly by the caller; it is not discovered, inferred, or generated by the learning/model pipeline.
- Executor identity must use the explicit `executor:` namespace.
- The executor receives the exact immutable handoff payload and environment identifier; the core service does not rewrite the request.
- A successful executor result must be a mapping and becomes immutable observed-result evidence with deterministic SHA-256 fingerprinting.
- Executor exceptions become immutable `FAILED` execution evidence with a non-empty failure reason; the core service does not silently retry.
- Preserves full v2 provenance, user authority identity, exact authorization scope, proposal fingerprint, handoff fingerprint, and execution identity.
- Execution evidence is recursively immutable.
- Source handoff remains unchanged.
- Invalid source type, blank execution ID, invalid executor identity, malformed READY authorization/scope, or invalid executor result fails closed.

## Authority walls

**Execution ≠ Authorization.**

**Execution ≠ User Intent.**

**Execution ≠ Learning.**

**Execution ≠ Proposal.**

**Execution ≠ Validation.**

**Execution ≠ Broader Permission.**

**Execution ≠ Scheduling.**

**Execution ≠ Policy Mutation.**

**Execution ≠ New Authority.**

The executor can act only because an already-authorized, exact proposal-scoped handoff reached it. Execution cannot create or enlarge authority.

## Failure behavior

`READY + executor success → COMPLETED`

`READY + executor exception → FAILED`

`BLOCKED → REJECTED`

No automatic retry occurs at M23.65. Retry remains a separate consequence controlled by the later outcome/repair/retry architecture.

## Why this boundary exists

The architecture must not collapse `AUTHORIZED` into unrestricted capability invocation. M23.64 freezes the exact handoff; M23.65 is the only boundary allowed to cross from an authorized handoff into an execution attempt.

The resulting chain is:

`Outcome → Feedback → Learning Signal → Learning Signal Integrity → Learning Eligibility → Adaptation Proposal → Proposal Validation → Adaptation Authorization → Adaptation Handoff → Adaptation Execution → Execution Result → Outcome`

M23.65 therefore closes the action-side portion of the controlled self-improvement loop without allowing execution to become a new source of authority.
