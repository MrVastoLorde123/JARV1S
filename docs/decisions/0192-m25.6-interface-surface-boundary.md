# Decision 192 — M25.6 Interface Surface Boundary

## Status
IMPLEMENTED / AWAITING LOCAL VERIFICATION

## Purpose
M25.6 gives JARVIS its first real human-facing interface surface without moving lifecycle semantics into the interface layer.

The initial surface is a provider-neutral terminal interface. It submits operations through the canonical M25.5 adapter and renders responses, session state, and runtime activity derived from M25.3/M25.4.

## Scope

```text
Human
  ↓
TerminalInterfaceSurface       ← M25.6
  ↓
InterfaceAdapter               ← M25.5
  ↓
InterfaceBackend               ← M25.1
  ↓
SelfImprovementOrchestration   ← M25.2
  ↓
M24 lifecycle
  ↓
RuntimeActivityStream          ← M25.3
  ↓
InterfaceSessionStateProjector ← M25.4
  ↓
TerminalInterfaceSurface
```

## Surface behavior

- `submit()` creates a presentation-layer request envelope and delegates through `InterfaceAdapter`.
- Request/session/actor identity remains explicit and is passed into the canonical backend contract.
- Responses remain backend-owned; the surface only renders their stable external representation.
- `status` renders the derived per-session `InterfaceSessionState`.
- `activity` renders immutable activity events belonging to the surface session.
- `submit <OPERATION> [JSON]` provides a usable terminal command path.
- `help` and `quit` provide minimal interactive shell behavior.
- Activity projection consumes new global stream events and lets M25.4 apply per-session strict ordering without assuming global sequence contiguity inside one session.
- Presentation errors remain interface errors; the surface does not manufacture lifecycle artifacts.

## Explicit non-powers

```text
Interface Surface ≠ Authority
Interface Surface ≠ Orchestration
Interface Surface ≠ Executor
Interface Surface ≠ Persistence
Interface Surface ≠ M24 Semantic Boundary
Interface Surface ≠ AI Provider
Interface Surface ≠ Truth / Certainty
```

The surface owns human interaction and presentation only. It cannot redefine operation meaning, directly call M24 services, execute capabilities, authorize execution, persist runtime state, or establish truth.

## Design consequence

JARVIS now has a real face without coupling the core to a GUI framework. The terminal surface establishes the reusable UX contract that later GUI, HTTP, API, and voice surfaces can consume through the same M25.5 boundary.

The first surface is intentionally small: command submission, response rendering, session status, activity history, and an interactive loop. Rich visual UX is deferred until real usage exposes what the interface should optimize for.

## Verification
Focused verification must cover dependency validation, request submission through M25.5, response rendering, immutable external responses, session-state refresh, activity filtering, command parsing, interactive loop behavior, error handling, request identity generation, and non-authoritative/non-persistent walls.

Local verification is pending and must be performed against the focused test, the M23.169→M25.6 regression chain, and the full `src/core/tests` suite before this decision is marked VERIFIED.
