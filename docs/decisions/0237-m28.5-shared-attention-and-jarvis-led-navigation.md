# M28.5 — Shared Attention and JARVIS-Led Navigation

## Decision
The living-world interface should distinguish **attention direction** from **shared attention**.

A directional highlight tells the operator where to look. Shared attention makes the environment behave as though JARVIS is actively bringing the operator into the region where meaningful work is occurring.

## Interaction model
When a real gateway state indicates meaningful activity, the environment may:

- shift the spatial frame toward the relevant region;
- temporarily increase spatial scale and saliency near that region;
- reduce unrelated regions to depth rather than hiding them;
- animate the transition as a short journey rather than an instant selection change;
- preserve the central JARVIS core as a reference point while the operator's attention follows the work;
- return to a neutral shared space when the work settles or no longer merits attention.

The ambient guide may express a relationship such as `Come with me`, `Stay with me`, `Look at this with me`, or `I need you here`, but it remains presentation-only.

## Authority boundary
The guide and world choreography never become an authority path. Backend state remains authoritative. The UI can invite attention, frame context, and expose controls, but it cannot infer user intent or grant itself permission from visual saliency.

## Design constraints
This mechanism is explicitly not:

- an autoplay slideshow;
- a notification system with prettier graphics;
- a permanent HUD;
- a camera/3D dependency;
- a replacement for deterministic backend state.

The target feeling is: **JARVIS is already doing something, and the environment lets the operator join him there.**

## Evidence in current prototype
The existing demo gateway already produces real transient states such as `Thinking` and `Working`, and returns to `Waiting`. M28.5 binds the environment's spatial framing to those states rather than inventing a parallel simulated activity timeline.
