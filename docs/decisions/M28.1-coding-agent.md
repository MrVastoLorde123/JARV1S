# M28.1 — Coding Agent Boundary

## Decision
JARVIS treats coding as an explicit agent role with a typed observable lifecycle. The coding agent may understand a task, propose a bounded plan, await confirmation, execute through existing tool authority, and report verification. It does not become an authority system.

## Contract
- Planning is proposal, not authorization.
- Confirmation is the explicit transition into coding execution.
- File edits remain bounded `write_file` tool requests.
- Verification remains a constrained `run_test` operation; the worker does not expose an arbitrary shell surface.
- Coding state reports lifecycle and evidence without exposing private model rationale.
- Existing coding confirmation, fingerprint, authorization, execution, and verification services remain the authority boundaries.

## Acceptance
The M28 contract tests validate lifecycle transitions, terminal-state behavior, and safe edit bounds. Existing coding-worker tests remain the execution-boundary regression gate.
