# M27.29 — Selected Mission Continuity

## Decision

Mission Flow state must resolve against the user's selected project when one is selected, rather than always resolving against the first active project.

## Contract

The selected mission is presentation context shared by Mission Spine, HOME Mission Flow, and Mission Control Pipeline. A snapshot remains the source of truth for runtime state; selection only determines which project/workspace is being inspected.

The derived state exposes project identity, workspace identity, model identity, current stage, evidence, guard condition, and next transition. It must not invent hidden reasoning, execution, authorization, tool completion, or verification.

## Rationale

Without selected-mission continuity, changing the project in Projects or Mission Control could leave the persistent mission surfaces describing a different project. That breaks the spatial continuity that makes JARVIS feel like one operating environment.

## Scope

Presentation and state-projection only. No authority, execution, or backend behavior changes.
