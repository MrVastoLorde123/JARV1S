# Decision 193 — M26.1 Runtime Kernel Boundary

Status: IMPLEMENTED / VERIFIED LOCALLY

## Context

M25 completed the external interaction path: interface backend, self-improvement orchestration, runtime activity, session projection, adapter translation, and terminal surface. Those contracts are individually bounded, but they still require a composition root to exist as one running JARVIS system.

## Decision

M26.1 introduces `JarvisRuntime` as the composition root for the verified M25 stack.

The runtime SHALL:

- accept an injected `InterfaceOrchestrationPort` rather than define lifecycle semantics itself;
- construct one `RuntimeActivityStream` and `InterfaceRuntimeActivityRecorder`;
- wrap orchestration with `ObservableInterfaceOrchestration` so requests and responses become observable runtime activity;
- construct `SelfImprovementInterfaceBackend`, `InterfaceAdapter`, `InterfaceSessionStateProjector`, and `TerminalInterfaceSurface` around that path;
- expose a small runtime API for `submit`, terminal line handling, status, activity, and terminal execution;
- preserve request, session, actor, operation, response, provenance, and activity semantics owned by M25;
- remain in-memory and composition-focused for this milestone.

The runtime SHALL NOT become an authority layer, executor, capability registry, persistence layer, truth/certainty oracle, or AI/model provider.

## Data flow

```text
Terminal / future interface
        ↓
TerminalInterfaceSurface
        ↓
InterfaceAdapter
        ↓
SelfImprovementInterfaceBackend
        ↓
ObservableInterfaceOrchestration
        ↓
Injected InterfaceOrchestrationPort
        ↓
M24 lifecycle
```

Observability flows alongside orchestration into the M25.3 activity stream, while M25.4 projects session state from those observations.

## Consequences

JARVIS has an explicit composition root without coupling the runtime to a particular model, tool executor, persistence implementation, or future UI. Later milestones can replace the injected orchestration implementation, add capability registration, introduce model-provider boundaries, and add persistent memory without changing the runtime's authority boundary.

## Verification

M26.1 was verified locally with:

- 8/8 focused runtime-kernel tests;
- 266/266 M25/runtime regression tests;
- 3113/3113 full `src/core/tests` suite.

The verification confirms runtime composition, end-to-end request/response observation, session-derived status and activity, terminal handling, identity validation, orchestration integration, and non-power guarantees.
