# Decision 188 — M25.2 Self-Improvement Orchestration Boundary

## Status
IMPLEMENTED / VERIFIED LOCALLY

## Purpose
M25.2 connects the provider-neutral M25.1 interface backend to the existing M24 continuous-self-improvement lifecycle.

The orchestration service is a routing boundary, not a new authority boundary. It accepts an immutable interface request, selects a fixed M24 stage, forwards the declared payload to the injected M24 service, and returns the resulting M24 artifact inside an immutable interface response.

## Scope

```text
InterfaceRequest
      ↓
SelfImprovementInterfaceBackend
      ↓
SelfImprovementOrchestration       ← M25.2
      ↓
M24.1 Candidate
      ↓
M24.2 Evaluation
      ↓
M24.3 Decision
      ↓
M24.4 Application
      ↓
M24.5 Verification / rollback evidence
```

M25.2 implements the five live lifecycle routes:

- `PROPOSE` → `ContinuousSelfImprovementCandidateService.propose`
- `EVALUATE` → `ImprovementEvaluationService.evaluate`
- `DECIDE` → `ImprovementDecisionService.decide`
- `APPLY` → `ImprovementApplicationService.apply`
- `VERIFY` → `ImprovementVerificationService.verify`

`ROLLBACK` is intentionally rejected because M24.5 records rollback evidence but does not execute rollback. `STATUS` is intentionally deferred until the runtime state contract is introduced downstream in M25.3/M25.4.

## Boundary rules

- Operation routing is an explicit enum map; no dynamic method lookup from caller input.
- Each M24 service is dependency-injected and must expose its expected method.
- Required payload fields are checked before the M24 service is called.
- Upstream M24 artifact types are validated before service delegation.
- M24 exceptions caused by malformed input become interface-level `REJECTED` responses.
- Unexpected failures become interface-level `FAILED` responses without manufacturing an artifact.
- Returned artifacts must be the exact M24 stage type expected for the requested operation.
- Request ID, session ID, actor ID, and operation identity are preserved.
- M24 artifact identity, provenance, lineage, status, and immutability are preserved by returning the artifact itself rather than reconstructing it in M25.2.

## Explicit non-powers

```text
M25.2 Orchestration ≠ Authority
M25.2 Orchestration ≠ Execution Engine
M25.2 Orchestration ≠ Persistence
M25.2 Orchestration ≠ AI Provider
M25.2 Orchestration ≠ M24 Semantic Boundary
M25.2 Orchestration ≠ Rollback Executor
```

The orchestration service must not authorize execution, execute capabilities, mutate state, persist state, establish truth, or establish certainty.

## Design consequence

The interface now has a real backend path into JARVIS's self-improvement machinery without allowing the interface layer to redefine the meaning of any M24 stage. Future GUI, CLI, HTTP, local API, and voice adapters can all consume the same orchestration contract.
