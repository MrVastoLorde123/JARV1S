# Decision 0203 — M27.13 Interface Command Center

**Status:** IMPLEMENTED ON `feature/m27.13-interface-command-center` / AWAITING LOCAL BUILD VERIFICATION

M27.13 continues interface-first development from the verified M27.10 direction. The goal is to make JARVIS feel like a desktop operating environment rather than a generic website dashboard.

## Interface boundary

The interface now reserves a first-class **ORCHESTRATION** surface on HOME. It communicates the intended observable lifecycle:

**Observe → Reason → Assign → Execute → Verify**

Model lanes expose role/state at a glance, while a dedicated reasoning-visibility area establishes where future backend-backed evidence will appear.

This is intentionally an interface contract, not fabricated backend state. The current implementation labels the orchestration view as an interface preview.

## Visual direction

- Glass-black surfaces are the dominant material.
- Blue remains an accent rather than the primary surface color.
- Sidebar navigation is denser, quieter and more application-like.
- Panels should read as operating surfaces, not marketing cards.
- Interaction states, focus states and hierarchy should remain visible without excessive decoration.
- HOME remains an orientation/command-center surface; MIND remains the deeper cognitive environment.

## Future observability

The interface should eventually make visible, where backend contracts permit:

- active project and current objective
- orchestration phase
- model/agent assignments
- model handoffs
- tool/capability calls
- evidence and sources
- reasoning summaries/decision records
- verification results
- blocked/awaiting-user states
- resource pressure and concurrency decisions

The UI must display these as observable state and provenance, never as an alternative execution authority.
