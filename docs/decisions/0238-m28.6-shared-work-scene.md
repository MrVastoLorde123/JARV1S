# M28.6 — Shared Work Scene

## Decision

Test a stronger interpretation of the living-world UI: JARVIS should not merely point the user toward work. Work should materialize inside the shared environment so the user and JARVIS occupy the same operational context.

## Interaction model

- JARVIS activity produces persistent spatial artifacts rather than notification-like highlights.
- The most recent meaningful activity becomes the current work object and receives the strongest spatial presence.
- New activity enters the environment as an arrival event, making change itself observable.
- Thinking, learning, working, monitoring, waiting, decision-required, and offline conditions alter the behavior of the shared work scene.
- The environment remains primary; the scene is ambient and non-interactive.
- The work scene does not grant authority or create backend transitions.

## Design hypothesis

Earlier M28 iterations created spatial attention direction but still treated the user as an observer being told where to look. M28.6 instead tests whether a continuously materializing work surface can create a sense of shared activity: JARVIS acts in the world, the world records those actions, and the user witnesses the work becoming real without opening a page.

## Research influence

This experiment draws from calm technology's movement between peripheral and central attention and from diegetic interface principles where system information exists as part of the environment rather than as detached application chrome.

## Non-goals

- No fake avatar or anthropomorphic JARVIS character.
- No 3D engine.
- No scripted cinematic sequence that claims backend work occurred when it did not.
- No permanent dashboard replacement for focused task UI.
