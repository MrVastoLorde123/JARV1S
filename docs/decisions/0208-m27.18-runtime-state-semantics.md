# M27.18 — Runtime State Semantics

## Decision
JARVIS interface modes must communicate meaningful runtime transitions rather than cycle automatically for visual activity.

## Behavior
- **Thinking** appears when a request is being interpreted or a research/planning thought is opened.
- **Working** appears when a project procedure is initiated or resumed.
- **Learning** remains available for real learning/verification integration and is not entered by a timer.
- **Waiting** is the stable idle state after a transient operation settles.
- Resource telemetry may continue to change independently so the environment remains visibly alive without inventing cognitive activity.

## Boundary
The demo gateway may simulate telemetry, but it must not simulate hidden reasoning or imply that work is occurring without an initiating event.

## Rationale
Dynamic behavior is useful only when it communicates system state. Replacing phase cycling with event-driven transitions makes the interface interpretable and provides a path for real backend runtime records to replace the demo behavior.
