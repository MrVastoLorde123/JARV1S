# M34.1 — Bounded Work Dispatch

M34 establishes the dispatch boundary between an already-selected `WorkPlanStep` and a concrete bounded worker assignment.

## Decision

A dispatcher may bind one planned step to one registered worker when the worker satisfies the step's required capabilities and assignment bounds.

The resulting `WorkerAssignment` remains non-authorizing. Dispatch does not create authorization, confirmation, execution requests, tool handles, credentials, or verification results.

## Boundary

M31 defines work state. M32 defines bounded plans. M33 coordinates progression through those plans. M34 binds a selected step to an existing bounded workforce contract. Existing M7/M8 authority and execution, plus M8.5 controlled agency, remain downstream and authoritative.

## Invariants

- the step must exist in the source plan
- the worker must exist in the `WorkerRegistry`
- every required capability must be present on the worker
- registry validation must accept the resulting assignment
- dispatch output explicitly reports `authorization_granted=False` and `execution_requested=False`
