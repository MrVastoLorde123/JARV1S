# M27.17 — Desktop Presence

## Decision
JARVIS should maintain a persistent desktop identity layer independent of the active functional space.

## Intent
The interface must feel like entering one operating environment rather than navigating a collection of application pages. HOME, CHAT, WORK, CONTROL, MIND, CAPABILITIES and SELF remain distinct views, but JARVIS itself should remain continuously present.

## Presence signals
The persistent layer exposes only presentation-safe state:

- JARVIS identity and operating-environment label
- current interface space
- current system focus
- current mode and latest structured event
- live local clock
- runtime uptime
- pressure/online state styling

## Boundary
Desktop presence is observational UI. It does not create authority, execute work, grant permissions, expose hidden model reasoning, or replace backend contracts.

## Implementation
`desktopPresenceController.ts` mounts a persistent DOM layer and subscribes to the existing `demoGateway` so the layer follows live demo state without duplicating the application state machine. Styling is isolated in `desktop-presence.css` and loaded from `main.tsx`.

## Direction
Future backend integration should replace demo snapshot/event sources with canonical session, mission, workspace, runtime and verification records while preserving the desktop presence contract.
