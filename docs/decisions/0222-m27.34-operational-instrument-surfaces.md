# M27.34 — Operational Instrument Surfaces

## Decision
CHAT, CONTROL, MIND, and CAPABILITIES are treated as distinct instruments within one JARVIS operating environment rather than as four pages sharing a shell.

## Surface semantics
- **CHAT / Intent Membrane:** receives language, direction, desired outcomes, and workspace scope. It does not imply execution authority.
- **CONTROL / Action Console:** exposes the selected mission, runtime state, model hand, authority path, and next actionable effect.
- **MIND / Context Field:** exposes the structured context layer around focus, memory, learning, plans, work, and relationships. It is not equivalent to chat history.
- **CAPABILITIES / Ability Fabric:** exposes available capability records and their lifecycle from discovery through scoped invocation and verification. Presence does not imply permission.

## Implementation rule
The new instrument layer is additive and mounted around the existing functional surfaces. Existing submit, project-control, navigation, workspace, research, planning, and authorization-oriented behavior remains the authority path.

## Visual language
Each instrument uses its own composition, vocabulary, metrics, and structural motif while inheriting the same material system, state-driven environment, mission continuity, and light/dark theme behavior.

## Principle
JARVIS should feel like one machine with different instruments: intent enters through CHAT, action converges in CONTROL, context lives in MIND, and available power is exposed through CAPABILITIES.
