# M28.1 — State-Driven JARVIS OS Behavior

## Decision
The JARVIS OS prototype uses runtime state to change visual weight and spatial emphasis, not merely status color.

## Rules
- ACTIVE keeps the current operation visually stable and prominent.
- WAITING quiets secondary structure while preserving the direct JARVIS input path.
- ATTENTION increases the prominence of the current operation and operator decision surface.
- GUARDED reduces background emphasis and reinforces the constrained transition.
- OFFLINE reduces saturation, weakens active pathways, and preserves the last-known operating context.

## Boundary
This is presentation behavior only. It reads the existing JarvisSnapshot contract and does not mutate backend authority, infer private reasoning, or create execution permission.

## Rationale
JARVIS should feel like an operating environment whose condition is visible in its behavior. State changes should make the environment reorganize its attention without causing the underlying navigation or object model to fragment.
