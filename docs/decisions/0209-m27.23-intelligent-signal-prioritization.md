# M27.23 — Intelligent Signal Prioritization

## Decision
SIGNAL is a prioritized communication channel, not a mirror of JARVIS's current mode.

JARVIS should decide what is most worth telling the user from presentation-safe state already available to the interface. The selected message should be the highest-value truthful signal at that moment.

## Priority order
1. Core availability or connectivity failure
2. Explicit user attention requirement
3. High resource pressure that changes system posture
4. Paused project state that may require intervention
5. Elevated resource pressure
6. Waiting project or other meaningful blocked context
7. Active project progress
8. Active plan progress
9. Research insight already present in canonical state
10. Learning/thinking/working context
11. Quiet readiness when nothing materially needs to be surfaced

The exact numeric scores are implementation details; the ordering is the behavioral contract.

## Message rules
Signals must be concise, truthful, and grounded in existing snapshot data. SIGNAL must not invent work, imply hidden reasoning, or convert telemetry into cognition.

A signal may be useful even when it is not urgent, but urgency must dominate novelty. The system should prefer one meaningful message over many competing messages.

## Boundary
The prioritizer is presentation-layer logic. It selects and phrases already-authorized state for display. It does not execute actions, create authority, mutate canonical state, or bypass policy/confirmation boundaries.

## Evolution
This establishes the first explicit signal-selection contract. Future work may move the prioritization source closer to canonical runtime/attention semantics once those contracts exist; the interface should not become the authority for what the system actually intends.
