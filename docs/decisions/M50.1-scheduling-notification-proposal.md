# M50.1 — Scheduling / Notification Proposal Boundary

M50 introduces an explicit proposal layer between proactive proposals and any future scheduling/notification runtime.

A proposal may describe a desired mode and bounded time window, but the object itself has no scheduling, notification, authorization, provider-selection, or execution authority.

Temporal data is descriptive input only. It must be timezone-aware when present and must satisfy its declared ordering constraints.

M50 therefore preserves the architecture boundary:

`Proactive Proposal -> Scheduling/Notification Proposal -> Confirmation/Authorization -> Runtime`
