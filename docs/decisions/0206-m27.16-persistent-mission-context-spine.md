# M27.16 — Persistent Mission Context Spine

## Decision
Introduce a persistent Mission Context Spine inside the JARVIS desktop layout.

The spine is a presentation layer over the existing `JarvisSnapshot`. It keeps the currently selected work object, workspace context, orchestration stage, active model, capability availability, resource strategy, authority boundary, and recent structured trace visible while moving between JARVIS spaces.

## Why
M27.14 established Mission Control as an observable orchestration surface, while M27.15 established coherent desktop theming. The next interface problem is continuity: Home, Chat, Work, Control, Mind, Capabilities, and Self should feel like different views of the same operating environment rather than separate pages.

A persistent context rail solves that without duplicating the navigation system or changing backend authority.

## Interface contract
The spine exposes four layers:

1. **Live mission** — selected project plus the current JARVIS focus.
2. **Route** — context, current orchestration stage, and assigned model.
3. **State** — current JARVIS mode and latest structured activity.
4. **Context bindings** — project, workspace, capabilities, and authority/resource indicators.

An expandable trace drawer presents structured activity only. It does not claim to reveal hidden model chain-of-thought.

## Boundary
M27.16 is presentation-only.

The spine does not authorize actions, execute capabilities, assign authority, or bypass policy. Navigation and selection remain UI state. Future backend trace records can replace the current preview snapshot without changing the visual contract.
