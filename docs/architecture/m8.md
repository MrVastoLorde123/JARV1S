# M8 — Agency Architecture

## Boundary

M7 ends at a provider-neutral `READY` execution handoff. M8 owns controlled execution and the return path from execution into JARVIS's observed state.

```text
M7 Authority
    ↓
READY ExecutionRequest
    ↓
M8 Agency
    ↓
Capability / Plugin
    ↓
Execution
    ↓
Result / Error
    ↓
Observation
    ↓
Context / State Update
    ↺
```

## Milestones

| Milestone | Responsibility |
| --- | --- |
| M8.1 | Execution Runtime |
| M8.2 | Capability / Plugin Execution Boundary |
| M8.3 | Execution Result + Observation Integration |
| M8.4 | Execution Lifecycle / Continuation |
| M8.5 | Controlled Multi-Step Agency |
| M8.6 | Agency Reliability / Recovery |

## Core invariants

- `READY` is not `EXECUTED`.
- Execution cannot grant, change, or infer authorization.
- `ATTEMPTED` is not `SUCCEEDED`.
- `FAILED` remains an observed failure.
- Capabilities and plugins provide execution, not authority.
- Continuation never implies authorization for a future action.
- Recovery and retry are bounded actions, not hidden autonomy.

## Workforce boundary

Workers are intentionally deferred to M9. A worker is an actor inside the agency system and must remain bounded by capabilities, inputs, outputs, lifecycle, and authority controls established by M7/M8.
